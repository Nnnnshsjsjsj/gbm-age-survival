# GBM Cohort Platform — app specification (MVP)

A research platform for students and young researchers working with glioblastoma survival data. The core promise: **bring your own small cohort, analyse it in your browser, and see your age effect next to the big public cohorts. Raw patient rows never leave your computer.** Only a numeric summary is shared, and only if the user chooses to.

## Stack and constraints
- Vite + React 18 + TypeScript-free JSX + Tailwind CSS 3. React Router with `createHashRouter` (the site is served from GitHub Pages under a sub-path).
- Dependencies allowed: react, react-dom, react-router-dom, papaparse, @supabase/supabase-js. Nothing else (no chart library; draw SVG by hand, the way `/home/claude/app/explorer_template.html` does).
- `vite.config.js`: `base: './'`, `build.outDir: '../docs/platform'`, `emptyOutDir: true`.
- The statistics engine already exists in `src/engine/` (see `ENGINE_API.md`; exported names: kaplanMeier, logRank, coxPH, schoenfeldTest, metaRandomEffects, describe, AGE_BANDS, ageBand). Do not modify it. Import it as ES modules. All computation happens in the browser. For cohorts above ~2,000 rows run coxPH inside a Web Worker (`src/workers/stats.worker.js`) so the UI stays responsive; below that, call it directly.
- Supabase is optional. Read `import.meta.env.VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`; if absent, the app runs in **local mode**: everything works except sign-in, sharing, community and admin, which show a short "Sign-in is not configured on this deployment" panel. Provide `.env.example`.
- Package.json already exists (engine tests). Merge, don't overwrite; keep `"type": "module"` and `"test": "node --test tests/*.test.js"`. Add `dev`, `build`, `preview`, `e2e` scripts.

## Routes
1. `/` **Home**: one sentence of what it is, three cards (Explore reference cohorts · Analyse your cohort · Pool the age effect), a plain "What this is not" box (not a prognosis tool, not medical advice, research and teaching only), and the privacy promise in one line ("Your file is read in this tab and is never uploaded").
2. `/explore` **Reference library**: loads `/reference/{tcga_gbm,cgga,msk_impact,cptac_gbm}.csv` (columns pid,AGE,OS_MONTHS,event,male,kps10,mgmt_meth,idh_mut; blanks are missing), computes KM by age band (AGE_BANDS from the engine) and the age Cox HR with the engine, shows the curves (SVG step plot with optional CI bands), a table (n, deaths, median OS, alive at 12/24 months) and the HR tile. Cohort switcher. Metadata per cohort: TCGA-GBM (USA, 1989–2013, "TCGA via cBioPortal gbm_tcga"), CGGA (China, 2006–2016), MSK-IMPACT (USA, 2014–2018, patients had to survive until sequencing), CPTAC-GBM (USA/international, 2016–2019, small, short follow-up). Small-group rule: never draw a curve for a group with fewer than 10 patients; show "fewer than 10 patients, not shown".
3. `/analyse` **Wizard** with 5 steps and a progress indicator: 
   - **Upload**: drag-and-drop or file picker for CSV/TSV (papaparse, `header: true, skipEmptyLines: true, dynamicTyping: false`). Also a button "Try the demo file" that fetches `/reference/demo_cohort_messy.csv`. Show file name, rows, columns. The file is parsed in memory only. State lives in a React context; nothing is written to storage.
   - **Map columns**: the standard field list is: age (years), survival time, time unit (days/weeks/months/years → convert to months, months = days/30.4375), status (event), sex, IDH, MGMT, KPS, extent of resection, radiotherapy, temozolomide, year of diagnosis. Required: age, time, status. Auto-suggest mappings by fuzzy header match (e.g. "Age at Dx" → age, "Survival (days)" → time with unit days, "Status" → status). For status, show the distinct values and let the user tick which value(s) mean "died" (auto-detect dead/deceased/1/true/yes/died). For sex/IDH/MGMT show distinct values with a mapping to male/female, mutant/wildtype, methylated/unmethylated, or "missing".
   - **Check**: run checks and show them as a list with pass/warn/fail: (a) rows dropped for missing required values (count); (b) time ≤ 0 rows; (c) age outside 0–100; (d) KPS not in 0–100 or KPS = 0 (flag: "KPS 0 means dead at assessment"); (e) suspicious columns that look like identifiers or names or full dates (headers matching /name|surname|patient|id|mrn|dob|birth|date/i, or values that parse as dates or look like free text) → warn "Looks like personal data. It is not used and never leaves this tab"; (f) fewer than 10 events → fail with explanation; (g) all events in {0,1} after mapping. Proceed only if no fail.
   - **Analyse**: run in this order and show: descriptives (n, deaths, median age with IQR, median OS with 95% CI from KM, alive at 6/12/24 months); KM curve of the whole cohort with CI band; KM by age band (small-group rule) with log-rank p; Cox age per year (HR, 95% CI, p, C-index) and, if the user mapped them, adjusted models mirroring the paper's nested set (age+sex, age+KPS, age+MGMT, age+IDH, age+all available), each with n and events; Schoenfeld p for age with a one-line reading ("no evidence the age effect changes over time" if p > 0.05); a "Methods paragraph" box that writes out what was done in plain sentences with the numbers filled in, with a Copy button.
   - **Compare**: forest plot with the user's age HR (highlighted) next to the four reference cohorts computed live and the pooled estimate from `metaRandomEffects` over reference cohorts + user's cohort; a sentence saying whether the user's CI overlaps the pooled interval; the between-cohort I². Then a **Share a summary** card: shows exactly what would be sent (JSON preview: cohort name, country, years of diagnosis (from/to), n, events, median age, age IQR, age-band counts with any band < 10 replaced by null, median OS, s6/s12/s24, models [{covariates, beta[], se[]}]), a checkbox "I confirm I have ethics approval or a public licence for this data", and a Send button that needs sign-in (Supabase magic link). In local mode the button shows the not-configured panel and a "Download summary as JSON" alternative.
4. `/pool` **Living meta-analysis**: lists reference cohorts + approved shared summaries (from Supabase table `cohort_summaries` where status='approved'; in local mode only reference cohorts), pooled HR per year with DerSimonian–Laird, Hartung–Knapp CI, I², prediction interval, leave-one-out table, forest plot. Also shows the published-cohort estimates from `/reference/published.json` (create it from `/home/claude/meta_out/meta_cohorts.csv`: rows with type=published; fields cohort, country, years, n, events, adjusted, idh, HR_year, lo_year, hi_year, url, pooled) as a second block, clearly labelled as taken from publications. Explain in one sentence why one row (Yang 2015) is shown but not pooled.
5. `/community` **Researchers**: needs Supabase. Profile editor (display name, institution, country, tags from a fixed list plus free text, short bio, "what data I work with"), a directory of profiles filterable by tag, and per-dataset discussion threads (datasets = the reference cohorts + approved summaries). Moderation rule: new threads are `pending` until an admin approves; replies post immediately and admins can delete. Show that rule in the UI.
6. `/admin` **Review queue**: visible only to users in the `admins` table. Approve/reject summaries with a note; approve/delete threads; delete replies.
7. `/about` About, methods, data sources, privacy (what is and is not collected), the "not a medical device" statement, contact via GitHub issues, link to the paper.

## Supabase
Use the schema in `supabase/migrations/0001_init.sql` (already written; read it and match table and column names exactly). Auth: magic link (`signInWithOtp`). Put the client in `src/lib/supabase.js` returning `null` in local mode. Keep every query behind a small `src/lib/api.js` so it is easy to test.

```json
  "n": 60, "events": 41, "median_age": 58, "age_iqr": [49, 66], "age_bands": {"<50": 12, "50-59": 18, "60-69": 20, ">=70": null},

```

## Copy rules
Short sentences. No hype. Never say "predict", "your survival", or "prognosis for you"; say "how groups fared", "the age effect in your cohort". The banner on Explore and Analyse: "Research and teaching tool. Group-level results from de-identified research data. Not for decisions about any person's care."
